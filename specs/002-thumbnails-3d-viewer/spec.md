# Feature Specification: Pipeline Grafica, Miniature e Viewer 3D On-Demand (`002-thumbnails-3d-viewer`)

**Feature Branch**: `002-thumbnails-3d-viewer`  
**Created**: 2026-11-27  
**Status**: Draft  
**Input**: Milestone M2 (`002-thumbnails-3d-viewer`) — Estrazione anteprime integrate (immagini creator, render piastra `.3mf`, preview `.lys`, riferimenti `.lyt`), analisi geometrica e rendering multi-angolo in background per modelli 3D residenti con cache deduplicata, griglia visiva zero-latency con hover scrub a 4 angolazioni e viewer 3D interattivo on-demand nell'Inspector e QuickLook (`Spazio`).

---

## Clarifications

### Session 2026-11-27

- Q: Quando un pack multi-file (cartella o archivio `.zip`) contiene molti file 3D e possiede già una foto del creator o un'anteprima `.3mf`/`.lys`, quali file devono ricevere il rendering automatico in background a 4 angolazioni? → A: Opzione A — Rendering in due fasi con priorità: prima vengono renderizzati il pezzo principale dei pack privi di foto/plate/preview e i file 3D singoli isolati (`single_file`), poi vengono completate in coda a priorità inferiore tutte le restanti mesh 3D residenti interne ai pack (anche se il pack possiede già una copertina immagine), così che anche la vista **Singoli File** e l'elenco pezzi dell'Inspector dispongano di miniature dedicate.
- Q: Come deve comportarsi l'applicazione con file 3D residenti molto pesanti o ad altissimo numero di triangoli in Passata 3 e nel Viewer 3D on-demand? → A: Opzione A — Soglie differenziate con conferma: in Passata 3 automatica le mesh oltre `100 MB` o `3 milioni` di triangoli vengono saltate con avviso recuperabile e fallback pulito; nel Viewer 3D on-demand i file fino a `100 MB` / `3 milioni` di triangoli si aprono direttamente, i file tra `100 MB` e `500 MB` (o oltre `3 milioni` di triangoli entro `500 MB`) richiedono conferma esplicita dell'utente prima del caricamento, e i file oltre `500 MB` vengono bloccati con messaggio esplicito.
- Q: Quando l'applicazione si avvia con un catalogo già esistente che contiene file residenti non ancora processati per miniature e geometria (ad esempio un database aggiornato da M1 o una Passata 3 interrotta chiudendo l'app), come deve comportarsi la pipeline in background? → A: Opzione A — Ripresa automatica all'avvio con Pausa/Stop: all'avvio, se esistono file residenti fermi a una passata precedente, Passata 2 e Passata 3 riprendono automaticamente in background senza ripetere la Passata 1, con controllo nella barra di stato per mettere in pausa o interrompere la coda.
- Q: Quando l'utente seleziona una scheda nella griglia per aprire l'Inspector laterale oppure cambia selezione mentre il viewer 3D nell'Inspector era già attivo, come deve comportarsi la viewport 3D dell'Inspector? → A: Opzione A — Attivazione esplicita e ritorno a 2D al cambio scheda: la selezione di una scheda apre sempre l'Inspector in modalità leggera 2D/metadati con pulsante dedicato per attivare il 3D, e al cambio di scheda la viewport 3D si smonta tornando alla vista 2D finché non viene nuovamente richiesta (mentre `Spazio` apre sempre direttamente il QuickLook 3D sospendendo l'eventuale istanza nell'Inspector).
- Q: Nella Passata 2, oltre all'immagine Hero selezionata come copertina di ciascun pack, quali altre immagini residenti (`.jpg`, `.png`, `.webp`) devono essere convertite nella cache miniature e come deve comportarsi il QuickLook su file immagine? → A: Opzione A — Tutte le immagini valide in cache per `Singoli File` e QuickLook 2D: Passata 2 converte nella cache locale tutte le immagini residenti non-banner/non-icona (incluse le foto secondarie dei pack/`.zip` e le immagini non associate con `model_id = NULL`), e il QuickLook aperto su qualsiasi file immagine residente ne mostra l'anteprima 2D senza montare il viewer 3D.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Estrazione automatica delle anteprime integrate da cartelle, `.zip`, `.3mf` e `.lys`/`.lyt` (Priority: P1)

Un utente con pacchetti di stampa 3D organizzati in cartelle o archivi `.zip` residenti desidera che il catalogo riconosca ed estragga automaticamente tutte le anteprime già fornite dai creator o dagli slicer — foto render del creator, anteprime piastra dei progetti `.3mf` e anteprime incorporate nei file `.lys` — senza mai scrivere file nelle proprie cartelle né scompattare gli archivi `.zip` su disco, e ricavando dai file `.lyt` i riferimenti ai modelli `.stl` collegati.

**Why this priority**: Moltissimi pacchetti commerciali o della community includono già immagini render ad alta qualità o anteprime piastra pronte; riutilizzarle immediatamente garantisce copertine fedeli a costo computazionale minimo rispetto al rendering 3D da zero.

**Independent Test**: Preparare una sorgente locale di test contenente: (a) una cartella pack con immagini render del creator più un'immagine banner/logo, (b) un archivio `.zip` residente con immagini creator e un file `.3mf` dotato di `Metadata/plate_1.png`, (c) un file `.lys` contenente `preview.png` incorporata, (d) un file `.lyt` con riferimenti a file `.stl`, ed (e) un file/archivio segnaposto *Online-Only*. Eseguire la scansione e verificare che: tutte le anteprime valide vengano estratte e salvate solo nella cache locale dedicata dell'applicazione, i banner/loghi vengano scartati quando sono disponibili render pertinenti, i riferimenti `.stl` del `.lyt` siano estratti nei dettagli del file/modello, nessun file venga estratto o scritto nelle cartelle utente e **0 byte** vengano scaricati per i segnaposto *Online-Only*.

**Acceptance Scenarios**:

1. **Given** una cartella pack o un archivio `.zip` residente contenente immagini `.jpg`, `.jpeg`, `.png` o `.webp` del creator (insieme a eventuali file accessori come `logo.png` o `banner.jpg`), **When** il sistema esegue la fase di estrazione anteprime, **Then** seleziona come copertina prioritaria l'immagine render del modello escludendo banner e loghi riconoscibili, senza estrarre o modificare alcun file nella cartella sorgente.
2. **Given** un file `.3mf` residente su disco oppure contenuto dentro uno `.zip` residente con una o più immagini di piastra (`Metadata/plate_*.png`), **When** il sistema ispeziona il pacchetto, **Then** estrae l'anteprima della piastra principale nella cache locale dell'applicazione (preferendo la piastra principale completa rispetto a varianti secondarie) senza decomprimere l'archivio su disco utente.
3. **Given** un file `.lys` residente con `preview.png` incorporata e un file `.lyt` residente con collegamenti a file `.stl`, **When** la scansione processa tali file, **Then** estrae e salva l'anteprima `preview.png` del `.lys` in cache senza dipendere da componenti proprietari e registra i percorsi di riferimento `.stl` ricavati dal `.lyt` affinché siano consultabili nei dettagli del modello.
4. **Given** un file `.3mf`, `.lys`, `.lyt`, un'immagine o un archivio `.zip` marcati come segnaposto *Online-Only*, **When** la fase di estrazione anteprime incontra tali elementi, **Then** salta completamente l'apertura dei contenuti, mantiene intatto il badge `Cloud / Online-Only` e produce **0 byte** di download dal cloud.

### User Story 2 - Analisi geometrica e rendering multi-angolo in background per modelli 3D residenti (Priority: P1)

Quando un modello o pacchetto residente (`.stl` binario o ASCII, `.obj`, `.ply`, `.glb`, `.3mf`) non possiede foto o anteprime già pronte — oppure per arricchire i singoli pezzi 3D — l'utente vuole che l'applicazione calcoli automaticamente in background le dimensioni reali in millimetri, il numero di triangoli e generi miniature multi-angolo (4 angolazioni) conservate in cache per impronta del contenuto, così da resistere a spostamenti/rinomine senza dover ricalcolare nulla.

**Why this priority**: Una grande quota di modelli scaricati contiene solo mesh grezze prive di immagini render; senza il calcolo metrico e il rendering multi-angolo automatico in background, la griglia resterebbe priva di riconoscibilità visiva per questi file.

**Independent Test**: Indicizzare un set residente di modelli misti (`.stl` binari e ASCII, `.obj`, `.ply`, `.glb`, `.3mf` senza anteprima piastra), inclusi un pack multi-file contenente sia un pezzo principale complesso sia micro-perni/basette minori (< 2.000 triangoli) e un archivio `.zip` residente di sole mesh. Verificare che in background vengano calcolati conteggio triangoli e dimensioni bounding box in `mm`, venga scelta la mesh più significativa come copertina del pack, venga salvata nella cache locale dell'applicazione una striscia a 4 viste deduplicata per impronta contenuto, e che dopo lo spostamento/rinomina del file la miniatura resti immediatamente disponibile senza ri-rendering.

**Acceptance Scenarios**:

1. **Given** file 3D residenti nei formati `.stl` (binario e ASCII), `.obj`, `.ply`, `.glb` e `.3mf` su disco o dentro un archivio `.zip` residente, **When** viene eseguita la fase di analisi geometrica e rendering in background, **Then** il sistema legge la geometria in memoria senza estrarre file nelle cartelle utente, calcola e memorizza il conteggio dei triangoli e le dimensioni del bounding box (`X`, `Y`, `Z` in `mm`) e genera una miniatura multi-angolo a 4 viste opache neutre tipo argilla salvata esclusivamente nella cache locale dell'applicazione.
2. **Given** un pack multi-file (cartella o `.zip` residente) privo di immagini creator e anteprime `.3mf`/`.lys`, contenente sia parti principali dettagliate sia piccoli perni o basette semplici, **When** il sistema sceglie la copertina del modello, **Then** seleziona automaticamente il pezzo 3D geometricamente più significativo evitando perni/basette minori quando esistono pezzi più ricchi.
3. **Given** due file identici oppure un modello spostato o rinominato su disco dall'utente tra una scansione e l'altra, **When** il sistema associa o aggiorna la miniatura tramite l'impronta del contenuto, **Then** riutilizza la miniatura già presente nella cache locale senza rigenerarla né duplicarla su disco.
4. **Given** modelli o archivi `.zip` in stato segnaposto *Online-Only*, **When** la fase di analisi geometrica e rendering è in esecuzione, **Then** tali elementi vengono saltati completamente senza aprire handle o scaricare dati (**0 byte** di traffico cloud).

### User Story 3 - Griglia visiva istantanea e *Hover Scrub* a 4 angolazioni (Priority: P1)

Mentre scorre migliaia di modelli e file nella griglia, l'utente vuole vedere le miniature apparire istantaneamente senza alcuno scatto, ruotare visivamente i modelli renderizzati in 4 angolazioni semplicemente muovendo il cursore in orizzontale sulla card, vedere le nuove miniature comparire progressivamente durante la scansione in background e disporre di un ripiego pulito per gli elementi privi di anteprima o *Online-Only*.

**Why this priority**: La fluidità dello scorrimento e l'ispezione visiva immediata a 4 angolazioni senza attivare scene 3D nella griglia rappresentano la promessa centrale dell'esperienza di navigazione di MeshCatalog.

**Independent Test**: Popolare il catalogo con migliaia di modelli e file con miniature già generate (mix di immagini creator, anteprime `.3mf`/`.lys`, strisce multi-angolo a 4 viste, schede prive di anteprima e segnaposto *Online-Only*). Verificare che: lo scorrimento della griglia resti fluido sotto la soglia di 16 ms per fotogramma senza istanziare alcun viewer 3D nelle card, il movimento orizzontale del cursore sulle miniature multi-angolo alterni immediatamente le 4 viste sia in vista **Modelli / Pack** sia in vista **Singoli File**, l'avanzamento in background aggiorni progressivamente le card visibili senza blocchi, e gli elementi senza anteprima o *Online-Only* mostrino il fallback pulito basato sul formato e sullo stato cloud.

**Acceptance Scenarios**:

1. **Given** schede nella griglia virtualizzata (in vista **Modelli / Pack** o **Singoli File**) dotate di anteprime in cache, **When** l'utente scorre rapidamente tra migliaia di elementi, **Then** tutte le miniature vengono caricate dalla cache locale senza istanziare scene 3D interattive nelle card e lo scorrimento mantiene una fluidità inferiore a 16 millisecondi per fotogramma.
2. **Given** una scheda la cui miniatura è una striscia multi-angolo a 4 viste generata da geometria 3D, **When** l'utente muove il cursore orizzontalmente da sinistra a destra sopra l'area dell'anteprima, **Then** l'immagine visualizzata cambia istantaneamente tra le 4 angolazioni corrispondenti alla posizione orizzontale del puntatore e ritorna alla vista principale all'uscita del cursore.
3. **Given** una scansione in background attiva che sta completando l'estrazione anteprime e il rendering multi-angolo, **When** nuovi gruppi di miniature vengono completati, **Then** le schede attualmente visibili nella griglia si aggiornano progressivamente in modo non bloccante senza interrompere la posizione di scorrimento o la ricerca corrente.
4. **Given** un modello o file privo di anteprima (es. `.gcode`, `.step`, mesh non ancora processata o danneggiata) oppure un segnaposto *Online-Only*, **When** la scheda viene renderizzata in griglia, **Then** mostra il fallback pulito basato su formato/contenitore ereditato dalla versione base (con badge distintivo `Cloud / Online-Only` quando applicabile).

### User Story 4 - Viewer 3D interattivo on-demand nell'Inspector e QuickLook (`Spazio`) (Priority: P1)

Quando l'utente desidera ispezionare davvero un modello o verificare un singolo pezzo contenuto in un pack o in uno `.zip` residente prima di decidere se stamparlo, vuole aprire su richiesta un viewer 3D interattivo direttamente nel pannello laterale (Inspector) o in una finestra rapida **QuickLook** attivabile con il tasto **`Spazio`**, ruotare e zoomare la mesh con illuminazione studio neutra, leggere dimensioni reali in `mm` e triangoli, attivare wireframe/griglia/assi, scegliere tra i vari pezzi del pack e liberare tutte le risorse grafiche alla chiusura.

**Why this priority**: Le miniature statiche/4-viste bastano per sfogliare, ma per valutare spessori, supporti e proporzioni reali di un pezzo è indispensabile l'ispezione 3D interattiva on-demand senza appesantire la griglia principale.

**Independent Test**: Selezionare nella griglia: (1) un pack multi-file su disco con più `.stl`/`.3mf`, (2) un archivio `.zip` residente con più file 3D, e (3) un file segnaposto *Online-Only*. Attivare la vista 3D nell'Inspector laterale e tramite QuickLook (`Spazio`); verificare la rotazione/pan/zoom fluidi con illuminazione argilla opaca, i toggle wireframe/griglia/assi, la visualizzazione di dimensioni reali (`mm`) e conteggio triangoli, il cambio di pezzo dentro il pack o lo `.zip` residente senza scrivere file temporanei su disco, il rilascio della memoria grafica alla chiusura e il blocco sicuro con messaggio esplicito sul segnaposto *Online-Only*.

**Acceptance Scenarios**:

1. **Given** una scheda residente selezionata nella griglia (un modello singolo, un pack o un singolo file 3D in vista **Singoli File**), **When** l'utente clicca per attivare la vista 3D nell'Inspector oppure preme il tasto **`Spazio`** per aprire il QuickLook, **Then** viene montata una singola viewport 3D interattiva con illuminazione neutra studio (clay/matcap), controlli di orbita, pan, zoom e ripristino inquadratura, oltre ai dati di dimensioni reali (`mm`) e conteggio triangoli.
2. **Given** la viewport 3D interattiva attiva nell'Inspector o nel QuickLook, **When** l'utente attiva o disattiva i controlli di ispezione (**wireframe**, **griglia piano di stampa**, **assi cartesiani**), **Then** ciascun ausilio visivo si aggiorna istantaneamente sulla scena 3D senza ricaricare la geometria.
3. **Given** un pack di cartella o un archivio `.zip` residente contenente più file 3D supportati (`.stl`, `.obj`, `.ply`, `.glb`, `.3mf`), **When** l'utente seleziona un altro pezzo dall'elenco del pack nell'Inspector o nel selettore del QuickLook, **Then** il viewer carica in memoria la geometria del pezzo scelto (senza estrarre file dallo `.zip` nelle cartelle utente), aggiorna la scena 3D e aggiorna le metriche geometriche (`mm` e triangoli) corrispondenti.
4. **Given** un'immagine non associata ad alcun modello nella vista **Singoli File** oppure un segnaposto *Online-Only*, **When** l'utente apre il QuickLook con `Spazio` o seleziona l'elemento nell'Inspector, **Then** per l'immagine non associata mostra l'anteprima 2D dell'immagine stessa (se residente) senza attivare un inspector modello inesistente, mentre per il segnaposto *Online-Only* **non** avvia il viewer né scarica il file, informando chiaramente che l'elemento è *Online-Only* e non residente localmente.
5. **Given** la viewport 3D montata nel QuickLook o nell'Inspector, **When** l'utente chiude il QuickLook (premendo `Spazio` o `Esc` o il pulsante di chiusura) oppure disattiva/chiude l'Inspector, **Then** la viewport viene smontata completamente liberando la memoria grafica e i buffer della geometria.

### Edge Cases

- **Immagini creator solo banner/loghi o miniature minuscole:** Se una cartella o `.zip` contiene immagini riconoscibili come loghi/banner/icone (es. nome contenente `logo`, `banner`, `icon`, `watermark`, `avatar`, `qr`, `patreon`, `socials`, oppure dimensioni o proporzioni marcatamente non da anteprima modello come icone piccolissime < 48 px o fasce ultra-strette), il sistema le scarta se esistono altre immagini valide o anteprime `.3mf`/`.lys`/3D; se l'unica immagine presente è un possibile banner ma non esistono altre sorgenti, non blocca il modello e ricade su eventuale render 3D o fallback pulito.
- **File `.3mf` privi di `Metadata/plate_*.png` ma con mesh valide (e viceversa):** Se un `.3mf` non contiene `Metadata/plate_*.png`, viene comunque analizzato geometricamente e renderizzato in 4 viste dalla propria mesh interna; se contiene `Metadata/plate_*.png` ma ha mesh malformata o vuota, l'anteprima piastra resta valida e l'errore geometrico viene registrato come avviso recuperabile.
- **File `.lys` senza `preview.png` o `.lyt` con percorsi relativi/rotti:** Se un `.lys` non contiene `preview.png` incorporata o è in un formato interno non leggibile in Tier 1, il sistema non fallisce la scansione, registra eventualmente un fallback pulito e procede; se un `.lyt` punta a percorsi `.stl` spostati o assenti, i percorsi estratti vengono comunque esposti come metadati testuali informativi senza tentare aperture forzate o idratazione di placeholder.
- **Mesh corrotte, vuote, con zero triangoli o dimensioni degeneri:** Se un file `.stl`, `.obj`, `.ply`, `.glb` o `.3mf` risulta troncato, sintatticamente corrotto, privo di triangoli validi o con bounding box nullo, la fase di analisi geometrica registra un avviso recuperabile sul file, non produce una miniatura vuota/corrotta e lascia la scheda con il fallback pulito (e l'eventuale apertura nel Viewer 3D mostra un messaggio di errore chiaro e non bloccante).
- **Mesh 3D molto grandi o ad altissimo numero di triangoli (es. statue multi-milione):** In Passata 3 automatica, le mesh residenti che superano `100 MB` di dimensione o `3 milioni` di triangoli vengono saltate senza interrompere la coda, registrando un avviso recuperabile e lasciando il fallback pulito sulla scheda. Nel Viewer 3D on-demand, i file fino a `100 MB` / `3 milioni` di triangoli vengono caricati direttamente; quelli tra `100 MB` e `500 MB` (o oltre `3 milioni` di triangoli entro `500 MB`) mostrano una richiesta di conferma esplicita (*"File pesante: X MB — carica comunque"*) prima di allocare la scena, mentre file oltre `500 MB` vengono bloccati con messaggio informativo di limite sicurezza superato.
- **Pack misti con alcuni file residenti e altri *Online-Only*:** Se una cartella pack contiene, ad esempio, una foto `.jpg` residente e file `.stl` *Online-Only*, il sistema estrae normalmente l'anteprima dalla sola foto residente (0 byte scaricati dai file *Online-Only*) e blocca il caricamento 3D solo per i singoli pezzi in stato *Online-Only*.
- **Ambiente privo di accelerazione GPU hardware compatibile:** Se sulla macchina target il renderer grafico off-screen non dispone di un adattatore hardware compatibile, il sistema utilizza un adattatore software compatibile ove disponibile oppure degrada in modo sicuro con avviso recuperabile mantenendo pienamente operative navigazione, estrazione immagini/plate e ricerca.
- **Spostamento file durante o tra scansioni con cache già popolata:** Se un utente sposta o rinomina una cartella o uno `.zip` mentre la miniatura è già in cache, al successivo passaggio la corrispondenza per impronta preserva la miniatura senza rigenerarla e rimuove i soli riferimenti orfani quando effettivamente non più usati da alcun modello/file in catalogo.
- **Tasto `Spazio` mentre il focus è in un campo di testo:** Premere `Spazio` dentro la barra di ricerca o un altro input testuale inserisce normalmente uno spazio nel testo e **non** apre il QuickLook; la scorciatoia `Spazio` attiva/chiude il QuickLook solo quando il focus è sulla griglia o sull'area di navigazione principale.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001 (Estrazione Anteprime Creator da Cartelle e `.zip` Residenti):** Durante la scansione estesa delle anteprime (Passata 2), il sistema MUST rilevare immagini `.jpg`, `.jpeg`, `.png` e `.webp` residenti associate a `folder_pack`, contenute dentro archivi `.zip` residenti (leggendole in memoria senza estrarre file su disco utente) oppure presenti come immagini non associate (`model_id = NULL`), filtrando ove riconoscibili banner, loghi, icone o asset accessori non rappresentativi del modello per la scelta della copertina Hero e convertendo nella cache locale dedicata tutte le immagini valide non scartate così da supportare sia la copertina del modello sia le anteprime individuali nella vista **Singoli File** e nell'Inspector.
- **FR-002 (Estrazione Render Piastra `.3mf`):** Per i file `.3mf` residenti su disco o contenuti dentro archivi `.zip` residenti, il sistema MUST ispezionarne il contenuto interno per estrarre le immagini render `Metadata/plate_*.png` (privilegiando `Metadata/plate_1.png` rispetto a varianti secondarie), salvando l'anteprima nella cache locale dell'applicazione senza scrivere file estratti nelle directory utente.
- **FR-003 (Supporto Lychee Tier 1 — `.lys` e `.lyt`):** Per i file `.lys` residenti (su disco o in `.zip` residenti), il sistema MUST ispezionare il contenitore senza ricorrere a librerie o SDK proprietari ed estrarre l'eventuale immagine `preview.png` incorporata nella cache locale. Per i file `.lyt` residenti, il sistema MUST estrarre l'elenco dei percorsi di riferimento ai file sorgente collegati (`.stl` e, ove presenti, `.obj`/`.3mf`) e renderli disponibili nei metadati di dettaglio del modello/file.
- **FR-004 (Priorità Deterministica Anteprima Hero di Modello/Pack):** Per ogni `Model` nella vista **Modelli / Pack**, il sistema MUST selezionare l'anteprima principale secondo l'ordine deterministico: (1) immagine render del creator, (2) immagine piastra estratta da `.3mf`, (3) `preview.png` estratta da `.lys`, (4) render multi-angolo generato dal pezzo 3D geometricamente più significativo del pack. Nella vista **Singoli File**, ogni scheda file mostra prioritariamente l'anteprima specifica di quel file (o la miniatura multi-angolo generata se è una mesh 3D).
- **FR-005 (Analisi Geometrica Mesh Residenti):** Nella fase di analisi geometrica in background (Passata 3), per ogni file residente (su disco o in `.zip` residente) nei formati `.stl` (binario e ASCII), `.obj`, `.ply`, `.glb` e `.3mf`, il sistema MUST calcolare e memorizzare nel catalogo il conteggio dei triangoli e le dimensioni reali del bounding box in millimetri (`X`, `Y`, `Z`).
- **FR-006 (Rendering Headless Multi-Angolo a 4 Viste e Selezione Pezzo Principale):** In Passata 3, il sistema MUST generare in background, senza aprire finestre visibili, una miniatura composita a 4 angolazioni cardinali con illuminazione studio neutra opaca tipo argilla (clay/matcap) eseguendo due livelli di priorità: (1) prioritariamente il pezzo principale dei pack privi di copertina immagine/plate/lys e i modelli `single_file` privi di anteprima dedicata (inclusi `.3mf` senza `Metadata/plate_*.png`), e (2) in coda a priorità inferiore tutte le restanti mesh 3D residenti interne ai pack (inclusi i pezzi di pack che possiedono già una copertina creator/plate/lys) affinché la vista **Singoli File** e l'elenco pezzi nell'Inspector mostrino miniature individuali. Le mesh che superano `100 MB` o `3 milioni` di triangoli MUST essere saltate in Passata 3 automatica con avviso recuperabile. Nei pack multi-file privi di copertina immagine, MUST selezionare il pezzo principale massimizzando la significatività geometrica (combinazione di complessità poligonale e dimensione del bounding box) ed evitando micro-componenti di servizio (< 2.000 triangoli) quando esistono mesh più ricche.
- **FR-007 (Cache Locale Esclusiva e Deduplicazione per Impronta):** Tutte le miniature estratte o renderizzate MUST essere salvate esclusivamente nella cache locale dedicata dell'applicazione (mai nelle cartelle utente) e indicizzate tramite chiave deterministica basata sull'impronta del contenuto; il sistema MUST riutilizzare le miniature esistenti in cache in caso di file duplicati, ri-scansioni su file invariati o modelli/archivi spostati e rinominati.
- **FR-008 (Invariante Anti-Idratazione M2 su Segnaposto *Online-Only*):** Il sistema MUST NOT aprire, leggere, decomprimere, analizzare geometricamente o renderizzare alcun file o archivio `.zip` identificato come segnaposto cloud *Online-Only*, garantendo esattamente **0 byte** di download dal cloud durante Passata 2, Passata 3 e durante qualsiasi interazione dalla griglia o dal viewer 3D.
- **FR-009 (Pipeline Background Non Bloccante, Ripresa Automatica e Controllo Coda):** L'estrazione delle anteprime (Passata 2) e il rendering geometrico (Passata 3) MUST essere eseguiti in background con indicatori di avanzamento visibili (fase attiva, conteggio elementi, elemento corrente ed eventuali avvisi recuperabili) e MUST notificare progressivamente l'interfaccia a batch affinché le schede visibili mostrino le nuove miniature appena pronte senza ricaricare l'intera griglia né interrompere ricerca o scorrimento. All'avvio dell'applicazione, se il catalogo locale contiene file residenti fermi a una passata precedente (es. database M1 o esecuzione interrotta), il sistema MUST riprendere automaticamente in background Passata 2 e Passata 3 per i soli elementi pendenti senza ripetere Passata 1, offrendo nella barra di stato un controllo esplicito per mettere in pausa o interrompere la coda.
- **FR-010 (Griglia Visiva Zero-Latency e *Hover Scrub* a 4 Angolazioni):** La griglia virtualizzata (in entrambe le viste **Modelli / Pack** e **Singoli File**) MUST visualizzare le miniature leggendo esclusivamente metadati locali e immagini pre-generate in cache, senza istanziare alcun contesto di rendering 3D interattivo nelle schede e mantenendo un budget di scorrimento fluido (< 16 ms per fotogramma). Quando una miniatura è un atlante a 4 angolazioni, il passaggio orizzontale del cursore sulla miniatura MUST commutare istantaneamente tra le 4 angolazioni in base alla posizione orizzontale del puntatore.
- **FR-011 (Fallback Pulito su Schede Senza Anteprima o *Online-Only*):** Le schede prive di anteprima in cache (perché non ancora processate, di formato non grafico come `.step`/`.gcode`, con mesh non valida, oppure in stato *Online-Only*) MUST visualizzare il layout pulito basato su formato/contenitore e stato cloud già definito in M1, senza mostrare immagini rotte.
- **FR-012 (Viewport 3D Interattiva On-Demand nell'Inspector e QuickLook `Spazio`):** Il sistema MUST fornire un'unica istanza di viewer 3D interattivo montata esclusivamente su richiesta all'interno dell'Inspector laterale o nel modale rapido **QuickLook** (attivabile e chiudibile con il tasto **`Spazio`** quando il focus non è in un campo di inserimento testo, oltre che con `Esc` o pulsante dedicato). Selezionando una scheda nella griglia, l'Inspector si apre in modalità leggera 2D/metadati (anteprima dalla cache, metriche, elenco file e pulsante per attivare il viewer 3D) e, cambiando scheda nella griglia, smonta l'eventuale viewport 3D precedente tornando alla vista 2D fino a nuova richiesta esplicita; l'apertura del QuickLook sospende/smonta l'eventuale viewport attiva nell'Inspector per garantire una sola scena 3D attiva. Il viewer MUST caricare direttamente file residenti fino a `100 MB` e `3 milioni` di triangoli, richiedere conferma esplicita dell'utente per file tra `100 MB` e `500 MB` (o oltre `3 milioni` di triangoli entro `500 MB`) e bloccare con avviso i file oltre `500 MB`. Il viewer MUST offrire illuminazione studio neutra (clay/matcap), controlli di orbita/pan/zoom/reset camera, toggle indipendenti per wireframe, griglia piano di stampa e assi cartesiani, e visualizzazione di dimensioni reali (`mm`) e conteggio triangoli.
- **FR-013 (Ispezione Singoli Pezzi da Pack o `.zip` Residente senza Estrazione):** All'interno dell'Inspector e del QuickLook di un `folder_pack` o `zip_archive`, l'utente MUST poter selezionare qualsiasi file 3D supportato contenuto (`.stl`, `.obj`, `.ply`, `.glb`, `.3mf`), caricandone la geometria direttamente in memoria (anche dall'interno di uno `.zip` residente senza scrivere file su disco utente) e aggiornando la scena 3D e le relative metriche.
- **FR-014 (Gestione Sicura Segnaposto Cloud e Anteprima 2D Immagini nel Viewer/QuickLook):** Quando l'utente tenta di aprire la vista 3D o il QuickLook su un file o pack in stato *Online-Only*, il sistema MUST bloccare il caricamento remoto, non forzare alcun download e mostrare un messaggio chiaro che l'elemento risiede solo sul cloud (visualizzando comunque un'eventuale copertina locale se già presente). Quando il QuickLook viene aperto su un file immagine residente (`.jpg`, `.jpeg`, `.png`, `.webp`) in vista **Singoli File** — sia associato a un modello sia non associato (`model_id = NULL`) — mostra direttamente l'anteprima 2D dell'immagine senza montare il viewer 3D e senza invocare dettagli modello quando `model_id` è assente.
- **FR-015 (Rilascio Risorse Grafiche alla Chiusura):** Alla chiusura del QuickLook, al collasso/disattivazione della viewport 3D nell'Inspector o al passaggio a un elemento privo di geometria 3D caricabile, il sistema MUST smontare la viewport 3D e rilasciare completamente la memoria grafica e i buffer della mesh caricata.

### Key Entities

- **ThumbnailAsset (Miniatura in Cache):** Asset immagine pre-generato conservato esclusivamente nella cache locale dell'applicazione (`cache_key` deterministica da impronta contenuto, percorso relativo locale nella cache, origine tra immagine creator / piastra `.3mf` / anteprima `.lys` / render multi-angolo, numero di fotogrammi `1` o `4` per hover scrub, dimensioni in pixel, timestamp creazione).
- **GeometryMetrics (Metriche Geometriche del File):** Attributi geometrici calcolati per ciascuna mesh 3D residente analizzata (conteggio triangoli, larghezza `X`, profondità `Y`, altezza `Z` del bounding box in `mm`), associati al `CatalogFile` e visualizzati in Inspector/QuickLook.
- **LycheeReferenceMetadata (Metadati Riferimento `.lyt`):** Elenco ordinato di percorsi di riferimento a file `.stl` sorgente estratti in Tier 1 da un file `.lyt` residente, esposti nei dettagli del file/modello.
- **Model & CatalogFile (Estensioni M2):** Le entità di M1 si arricchiscono del collegamento alla miniatura principale (sul modello e sul singolo file), delle metriche geometriche sui file 3D residenti e dello stato di avanzamento di indicizzazione fino alla Passata 3 (geometria e rendering).

### Scope Boundaries (Out of Scope for M2)

Le seguenti funzionalità sono esplicitamente escluse dalla milestone M2 e rimangono assegnate alle milestone successive:
- Motore tassonomico automatico a facce semantiche, dizionari e ricerca bilingue IT/EN, filtri per facce nella sidebar e correzione inline/override dei tag (Milestone M3).
- Mosaico **Smart Folder Card** (*1 Hero + 3 Thumbnails*) sulle schede delle cartelle e *Hover Scrub* a 12 modelli di cartella (Milestone M3; in M2 le cartelle mantengono le schede informative di M1).
- Connettore diretto Dropbox OAuth 2.0 PKCE, ispezione remota via richieste parziali `HTTP Range` e interruttore di rendering volatile in RAM per `.stl` remoti (Milestone M4).
- Gestione e pulizia duplicati, lancio slicer esterni (*Apri in Bambu Studio / Lychee Slicer*), classificazione AI Vision/CLIP locale ed estrazione mesh Lychee Tier 2 da `.lys` (Milestone M5 / v2+).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001 (Zero Download Cloud Involontari):** Su una cartella di test Windows contenente file e archivi `.zip` in stato *Online-Only*, l'esecuzione completa di Passata 2 (estrazione anteprime), Passata 3 (analisi geometrica e rendering), navigazione griglia e aperture QuickLook/Inspector produce **0 byte** di traffico di download dal cloud sul **100%** dei segnaposto.
- **SC-002 (Integrità Read-Only):** Al termine dell'estrazione anteprime da cartelle, `.zip`, `.3mf`, `.lys`/`.lyt`, del rendering multi-angolo e dell'apertura ripetuta di pezzi nel Viewer 3D, il **100%** delle cartelle e dei file utente monitorati presenta **0** file creati, modificati o estratti rispetto allo stato iniziale.
- **SC-003 (Copertura Anteprime & Precisione Selezione):** Su un dataset residente eterogeneo contenente immagini creator (con banner/loghi), `.3mf` con piastra, `.lys` con anteprima, `.lyt` con riferimenti e mesh `.stl`/`.obj`/`.ply`/`.glb`, almeno il **95%** dei modelli validi ottiene automaticamente una miniatura visiva pertinente (privilegiando nel **100%** dei casi configurati le copertine creator / piastra `.3mf` / preview `.lys` prima del render geometrico).
- **SC-004 (Fluidità Griglia & *Hover Scrub*):** Su una griglia popolata con almeno **10.000** schede dotate di miniature in cache, lo scorrimento verticale mantiene un tempo per fotogramma inferiore a **16 millisecondi** e l'*Hover Scrub* a 4 angolazioni commuta la vista in **meno di 16 millisecondi** senza istanziare alcun viewer 3D interattivo nelle schede.
- **SC-005 (Reattività Viewer 3D On-Demand & Pulizia Risorse):** L'apertura di un file 3D residente standard (fino a 50 MB / 1 milione di triangoli, da disco o da `.zip` residente) nel QuickLook (`Spazio`) o nell'Inspector mostra la mesh interattiva in **meno di 1,5 secondi**; alla chiusura della viewport, il rilascio della memoria grafica ritorna stabilmente ai livelli precedenti entro **1 secondo** senza accumulo progressivo su 20 aperture/chiusure consecutive.
- **SC-006 (Resilienza della Cache su Spostamenti):** Il **100%** dei modelli e archivi `.zip` spostati o rinominati localmente tra due scansioni riutilizza immediatamente la propria miniatura già salvata in cache tramite impronta del contenuto, evitando qualsiasi ri-rendering superfluo.

## Assumptions

- **Formato e dimensioni predefinite delle miniature in cache:** Ogni fotogramma è salvato in formato compresso ad alta efficienza a risoluzione quadrata predefinita (es. `256×256` px per anteprima singola; `1024×256` px disposti orizzontalmente per la striscia multi-angolo a 4 viste) nella cache locale dell'applicazione, offrendo elevata nitidezza sulle card desktop e occupazione contenuta su disco (~40–80 KB per asset).
- **Criterio euristico per esclusione banner/loghi:** Le immagini dentro un pack o `.zip` con nomi indicativi di asset accessori (`logo`, `banner`, `icon`, `watermark`, `avatar`, `qr`, `patreon`, `socials`, `badge`) o proporzioni marcatamente atipiche (icone microscopiche < 48 px o fasce molto allungate) vengono deprioritizzate o escluse quando sono presenti immagini render o sorgenti 3D/slicer alternative.
- **Soglia pezzi minori nei pack multi-file:** Nella scelta automatica del pezzo 3D più rappresentativo di un pack privo di foto/plate/preview, i componenti sotto i `2.000` triangoli (tipicamente perni, spine o basette lisce) vengono scartati ogni volta che nello stesso pack esistono mesh con complessità superiore; in caso contrario viene scelto il pezzo disponibile con il maggior prodotto `triangoli × diagonale bounding box`.
- **Unità metriche di riferimento:** I file `.stl`, `.obj` e `.ply` privi di metadati di unità espliciti vengono interpretati in millimetri (`mm`, standard de-facto della stampa 3D); per i formati con unità esplicite (`.3mf` con attributo `unit` e `.glb` in metri per specifica) le dimensioni vengono convertite automaticamente in `mm`.
- **Fallback in ambienti privi di GPU hardware dedicata:** Se il sistema host non espone un adattatore grafico hardware utilizzabile per il rendering off-screen, Passata 3 tenta il ripiego su renderer software compatibile o degrada con avviso recuperabile senza impedire Passata 1, Passata 2, la navigazione griglia o l'ispezione 3D nell'interfaccia.
- **Continuità dati e controlli con M1:** Le preferenze di filtro, la selezione cartelle, il toggle **Modelli / Pack** $\leftrightarrow$ **Singoli File** e la ricerca istantanea introdotti in M1 restano invariati e pienamente funzionanti; M2 arricchisce le schede, il pannello dettagli laterale e la pipeline di indicizzazione in continuità diretta con M1.
